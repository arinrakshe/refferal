# Participant Quickstart

## The Short Version

You have one day. Pick a real workflow problem, build the smallest useful AI-assisted prototype, keep it safe, and show it clearly.

## First 15 Minutes

- [ ] Confirm your account and network access.
- [ ] Find or form a team.
- [ ] Choose one challenge track.
- [ ] Pick one user and one workflow.
- [ ] Start `07-templates/team-proposal.md`.
- [ ] Decide who owns the final submission and demo.

## First 30 Minutes

- [ ] Write the problem in one sentence.
- [ ] Define what you can demo by 15:30.
- [ ] Choose synthetic or de-identified data.
- [ ] Identify where AI helps.
- [ ] Pick one trust/safety/transparency mechanism.
- [ ] Create a repo, folder, notebook, or shared workspace.
- [ ] Ask a TA if access, data, scope, or safety is unclear.

## A Good Hackathon Scope

Good:

- One user.
- One workflow.
- One AI-assisted step.
- One safe data path.
- One clear demo.

Too big:

- Many users.
- Many systems.
- Live production data.
- Complex auth.
- Autonomous clinical decisions.
- A demo that only works if several live services behave perfectly.

## The Project Sentence

Use this:

```text
For [user], who needs to [goal], our prototype helps them [benefit] by [AI-assisted workflow improvement].
```

Example:

```text
For a care team member reviewing upcoming visits, our prototype helps surface missing prep items by summarizing synthetic patient context and flagging gaps for human review.
```

## What Judges Need To See

- Who the user is.
- What pain point you solved.
- What changed in the workflow.
- What data you used.
- Where AI is used.
- Why the result is trustworthy enough for a prototype.
- What metric would prove it works.

## Ask For Help Early

Ask a TA when:

- You cannot access Codex or a needed endpoint.
- You are unsure whether data is allowed.
- Your scope is getting too large.
- Your demo depends on fragile live setup.
- You need help explaining the safety mechanism.
